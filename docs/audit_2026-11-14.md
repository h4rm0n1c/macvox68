# MacVox68 evidence audit — 2026-11-14

Baseline: `caeb8ad` (2026-01-07), plus the uncommitted fixes described here.
This is an initial source/history/reference audit, not a certification of the
application or its reusable helpers. No guest build or runtime test was done
in this pass. Old prose and commit messages establish intent, not correctness.

## What is already implemented

The programmatic window, About box, input dispatcher, shared layout/theme,
TextEdit fields and scrolling, radio group, slider/value-label helper and icon
generation pipeline are actual implementations. They are more than a mock-up,
but their lifetime, focus, allocation and old-system behavior need validation.

The network facade selects between an Open Transport TCP implementation and
a classic-networking refusal backend. The OT backend has four client slots,
nonblocking reads and UI callbacks. This is a transport scaffold, not a speech
request protocol: received chunks are appended to the text area, each with a
carriage return. TCP chunks do not establish message boundaries.

Speech is a separate smoke test. The Speak button calls
`speech_speak_test_phrase()`, not the editor contents or parser. Rate, pitch,
volume and prosody controls are not connected to speech synthesis. The parser
is compiled, but `main_window.c` and `speech.c` do not call it. This incomplete
wiring is distinct from defects in the component implementations.

## Parser reference comparison: confirmed divergence, not yet repaired

The owner identifies **NetTTS and VoxTalk** as the external reference projects
for their Half-Life VOX preprocessing code. These are not two independent
synthesis oracles. VoxTalk's parser explicitly identifies itself as a port of
the NetTTS preprocessor, separate from FlexTalk.dll synthesis logic.

Read-only local references:

- `/home/harri/nettts-release/src/vox_parser.cpp`: checkout `239f10f`, parser
  last changed by `4512a91` (2025-09-08).
- `/home/harri/voxtalk/src/vox_parser.cpp`: checkout `6b67cc9`, parser last
  changed by `1979492` (2026-08-10).

The comparison compiles only each parser and a tiny host driver. It does not
start the Windows applications, speech engines or RE services. On 34 ASCII
inputs with both wrapper settings, NetTTS and VoxTalk agree on **68/68**
outputs. MacVox agrees on **0/68**. This is a deliberately varied sample, not
exhaustive proof. The source hashes and exact outputs are preserved in
`parser_reference_comparison_2026-11-14.json`.

Specific findings:

- Empty and whitespace-only input returns NULL from MacVox, while both
  references return an allocated/string empty result. The harness records
  NULL explicitly rather than treating it as a crash.
- Even `Hello there.` loses the separating space before `\!sf500`.
  `vox_process_buffer()` inserts a space before `beats`, then appends the
  marker directly after it; both references append the space after the beats.
- Time expansion and `On behalf of The Board, please wait.` contain duplicate
  adjacent breaks in MacVox. Its `tidy()` only normalizes whitespace, unlike
  the reference normalization of tags. Existing substring checks actually
  require some of these duplicates, so passing those checks is not parity.
- `Now boarding.` has an extra trailing beat break; `A reminder to all
  personnel.` differs in internal break placement as well. Fixing whitespace
  alone will not establish equivalence. Compare the beat state transitions.
- Speech-command translation is a further, separately unvalidated stage.
  Wrapper recognition checks length 4 for five-character `\!wH1`/`\!wH0`
  tokens, making the intended comment-emission branches unreachable.
- The translator multiplies `\!sf500` by ten to produce a 5,000 ms silence.
  Both references do emit that marker; its intended synthesis semantics and
  a suitable Mac mapping still need vendor/Apple evidence and listening tests.
- Many builder append results are ignored and later stages assume successful
  allocations. The ownership fix does not establish allocation-failure safety.
- The public header's UTF-8 claim is unsupported by bytewise character
  processing and the System 7 Roman porting notes. This comparison is ASCII
  only; it establishes nothing about accented text or encoding conversion.

Do not connect this formatter to general speech on the strength of the three
old checks. Repair reference divergence stage by stage, retaining exact output
comparisons; then validate the Mac command translation separately.

## Compatibility findings requiring follow-up

**Appearance Manager is an undeclared runtime dependency.** `SetControlData`
is called unconditionally in `ui_windows.c` and `about_box.c`;
`network_backend_classic.c` calls `StandardAlert` unconditionally; slider
creation uses `kControlSliderProc` (48). There is no Appearance Gestalt gate.
Defining missing constants or including SDK headers does not install support.

Apple's Appearance SDK reference (corpus 162, pp. 21–22, 73 and 261) requires
checking `gestaltAppearanceAttr`, identifies the slider in its Appearance
control table, and explicitly marks StandardAlert as new with Appearance.
The local universal Controls.h and Dialogs.h also identify SetControlData and
StandardAlert with AppearanceLib 1.0 availability. Plain System 7.5.3 alone
does not justify these calls. This pass did not determine whether the current
guest has Appearance installed, so it does not claim the guest crashes.

`docs/slider_style_notes.md`'s blanket compatibility claim and the default
button guidance need that qualification. A proper fix needs a documented
baseline plus feature gates/fallback UI on systems without Appearance; merely
changing a proc constant would substitute a different control design.

**Keyboard focus can reach the background main window.** The About overlay
registers no key handler (`window_ui.c`). `ui_input_dispatch_key()` then falls
through to the main handler even when About is frontmost. Activation/suspend
events are not dispatched, while main idle processing still operates its
TextEdit state. Confirm with guest input, then give focus changes an explicit
contract before treating the dispatcher/TextEdit helpers as reusable.

**Networking has additional unresolved behavior.** Invalid bind text silently
becomes any-address; IPv4 parsing accepts trailing junk; the port field uses
strtol without an end-pointer check. InitOpenTransport's result is ignored.
The full-slot path logs rejection without actually rejecting the pending
connection, and the receive path handles T_DISCONNECT but not orderly release.
Exercise initialization failure, reconnects, backlog exhaustion and half-close
against the documented state machine. The receive-status fix covers none of
those cases.

**Speech state is global.** `SpeechBusy()` reports system activity, while the
app owns no explicit channel. It is not evidence that this application's
utterance remains active. Channel lifetime, long-text storage and completion
need design/validation before replacing the smoke test with real requests.

```sh
python3 tests/compare_parser_references.py \
  --nettts /home/harri/nettts-release --voxtalk /home/harri/voxtalk \
  --report /tmp/macvox-parser-parity.json
```

sanitizer command is in `parser_ownership_fix.md`. No mounted disk, original
image, emulator session or external reference project was changed.
